# 每周风控规避清单(生产)

每周跑一次,输出「本周不建议持有」的个股排名。

## 它是什么

研究结论的落地形态:**持有指数全部成分、按基准权重,把模型预测最差的一批权重置零。**
不是选股,是**不买最差的**。信号在交易日 **14:55** 可得(特征只用 09:30–14:55),
标签期 **5 个交易日**,所以清单覆盖签发日之后约一周的持仓期。

交付域是 `csi1000` 和 `gz2000` —— 冻结配置选定的两个域。
`csi500` / `hs300` 不入生产:前者风格中性化后留存率仅 37%,后者在测试段被证伪。

## 安装

```bash
cp .env.example .env      # 填 5 个数据根,见仓库根 README
crontab -e
```

```cron
# 每周一 17:30(A股收盘后)。信号本身 14:55 已可得,留出数据落库时间。
30 17 * * 1 /path/to/repo/ops/run_weekly.sh >> /path/to/repo/ops/logs/cron.log 2>&1
```

## 输出

| 文件 | 内容 |
|---|---|
| `ops/output/avoid_<信号日>.csv` | 排名最差 N 只:`rank, symbol, index, pct, weight, tradable` |
| `ops/output/avoid_<信号日>.md` | 同上 + 数据新鲜度、模型状态、不可交易只数 |
| `ops/output/latest.csv` | 最近一次的副本 |

`pct` 是**域内**百分位(越小越差)。**跨域只能比 `pct`,不能比 `score`** ——
score 是域内横截面秩目标的预测值,两个域各自标准化过,直接比大小没有意义。

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 正常 |
| **3** | 清单已产出,**但因子库陈旧,不代表当周信号** |
| 其它 | 失败 |

**3 必须接告警。** 定时任务最危险的失败不是崩溃,是数据源停更而任务照常"成功" ——
每周准时输出一份看起来正常、实际早已过期的清单。所以脚本把陈旧做成了非零退出码,
而不是日志里一行灰字。

## 重训节奏

**每 63 个交易日重训一次**(≈ 一个季度),不是每周。这与研究的 `REFIT_EVERY` 一致。

每周重训看起来更"新",实际有害:一周只增加 5 天样本,模型却会因随机性整体漂移,
且与回测口径不符 —— 回测里的 IR 3.47 是在 63 日重训节奏下测出来的,
换个节奏就不再是同一个东西。模型状态存在 `ops/state/model_<域>.pkl`,到期自动重训。

强制重训:`ops/run_weekly.sh --force-refit`

## 与研究代码的差异

1. **训练用全部可用历史,含原 test 段。** test 段封锁是研究纪律的对象,不是生产的;
   它已在 2026-08 一次性开封评估完毕,继续封锁只会让生产模型白白少用两年数据。
2. **重训按 63 交易日,不是每周**(见上)。
3. **只预测不评估。** 没有前向标签可用,脚本不产出任何收益数字 ——
   任何"本周表现"都得等 5 个交易日之后另行计算。

## 资源

| | 峰值 | 说明 |
|---|---|---|
| 内存 | **~300GB 瞬时** | `gz2000` 数据集 400 万行 × 742 特征, 加载与取值复制时叠加; 拟合期回落到 ~50GB |
| CPU | `--threads` 指定 | 默认 32; 实测 48 线程下 csi1000 拟合 ~730s(机器满载时) |
| 时长 | 首跑 ~30min | 之后只有每 63 交易日的重训才需要这个时长, 平常几十秒 |

内存尖峰在**数据加载**不在拟合。若机器吃紧, 用 `--indexes csi1000` 分两次跑,
两个域彼此独立, 分开跑结果完全一致。

## 已知限制

- **不可交易的股票仍会进清单**:停牌或跌停封板时当日卖不掉,报告会标出来,需顺延。
- **清单不是卖出指令**:它是"不持有"名单。已持仓的按可交易性择机减,未持仓的不建。
- **权重再分配未做**:剔除后剩余权重如何归一由下游组合模块决定,本脚本只给名单。
